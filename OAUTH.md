# OAuth Implementation Plan

## Overview
Upgrade the Astro blog's authentication system from basic email/password authentication to professional OAuth with Google using Better Auth.

## Current State Analysis ✅
- **Working**: Basic email/password auth with cookie sessions
- **UI**: Simple login form in `admin.astro`
- **Middleware**: Protects `/admin` routes with session checks
- **API Endpoints**: `/api/auth/login`, `/api/auth/logout`, `/api/auth/check`

## Implementation Steps

### 1. Install Dependencies
- Add `better-auth` package
- Add SQLite database support (`better-sqlite3`)
- Configure environment variables for OAuth

### 2. Database Setup
- Create SQLite database file
- Use Better Auth CLI to generate/migrate schema
- Configure database connection in `auth.ts`

### 3. Create Better Auth Configuration
- **File**: `auth.ts` (root level)
- Configure Google OAuth provider
- Set up database adapter (SQLite)
- Configure session management
- Add email/password fallback for backward compatibility

### 4. Create API Handler
- **File**: `src/pages/api/auth/[...all].ts`
- Mount Better Auth handler for all auth routes
- Handle GET/POST requests

### 5. Create Auth Client
- **File**: `src/lib/auth-client.ts`
- Vanilla client (no framework-specific client needed for Astro)
- Configure base URL and session management

### 6. Update Middleware
- **File**: `src/middleware.ts`
- Replace cookie-based session checks with Better Auth session validation
- Update redirect logic for OAuth flows

### 7. Update Admin UI
- **File**: `src/pages/admin.astro`
- Replace email/password form with OAuth login buttons
- Add Google OAuth button with proper styling
- Keep basic auth as fallback option

### 8. Update Admin Dashboard
- **File**: `src/pages/admin/dashboard.astro`
- Update logout functionality to use Better Auth client
- Add user info display from OAuth session

### 9. Environment Configuration
- Add Google OAuth credentials (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`)
- Add Better Auth secrets (`BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`)
- Update Docker environment

### 10. Migration & Cleanup
- Remove old auth endpoints (`login.ts`, `logout.ts`, `check.ts`)
- Update TODO.md to reflect OAuth completion
- Test OAuth flow and fallback auth

## Technical Details

### Database Schema (auto-generated by Better Auth):
- `user` table: id, name, email, emailVerified, image, createdAt, updatedAt
- `session` table: id, userId, token, expiresAt, ipAddress, userAgent, createdAt, updatedAt
- `account` table: id, userId, accountId, providerId, accessToken, refreshToken, etc.
- `verification` table: id, identifier, value, expiresAt, createdAt, updatedAt

### OAuth Flow:
1. User clicks "Sign in with Google"
2. Redirects to Google OAuth
3. Google redirects back with auth code
4. Better Auth exchanges code for tokens
5. User session created and stored
6. Redirect to admin dashboard

### Security Considerations:
- HTTPS required for production OAuth
- Secure cookie settings for production
- Proper CORS configuration
- Environment variable security

## Benefits of This Upgrade
- **Professional Auth**: Industry-standard OAuth implementation
- **Better Security**: Proper token management and session handling
- **Scalability**: Database-backed sessions vs. simple cookies
- **User Experience**: One-click login with Google
- **Maintainability**: Well-documented, actively maintained library

## Potential Challenges
- **Environment Setup**: Need Google OAuth app credentials
- **Database Migration**: Moving from cookie-based to database sessions
- **Testing**: OAuth flows require proper test setup
- **Production Deployment**: HTTPS and domain configuration for OAuth

## Prerequisites
- Google Cloud Console account for OAuth credentials
- HTTPS setup for production deployment
- Environment variable management
- Database backup before migration
